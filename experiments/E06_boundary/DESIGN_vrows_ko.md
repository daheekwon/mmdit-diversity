# 이미지 행 V 편집 변형 비교 설계안 (초안, 2026-11-06, 실행 전)

E06 결과(E3, 엄격 실패 라벨 §21)를 본 뒤에 쓴 설계안이다. 사전 등록에는 없었다. 아직 코드도 큐도 없다. 사용자가 승인하면 PROTOCOL에 절로 옮기고, 판정 규칙은 결과를 보기 전에 고정한다.

## 0. 질문

지금 V 편집은 V 모듈 출력(to_v)을 바꾼다. 그래서 같은 블록의 텍스트 쿼리도 편집된 이미지 V를 읽는다(`div/models.py` `_SD35Processor`·`_FluxProcessor`, `div/method.py` `attend`의 텍스트 출력). pad 축소는 이와 달리 이미지 쿼리 행에만 적용된다.

- **Q1 (채택):** V 편집을 이미지 쿼리 행에만 적용하면(이하 "이미지 행 V 편집"), 같은 다양성에서 지금 방식보다 실제 실패나 불일치가 적은가?
- **Q2 (서술):** 같은 블록에서 텍스트 쿼리가 편집된 V를 직접 읽는 몫은 다양성의 얼마인가? E3 텍스트 스트림 고정(같은 step 안의 텍스트 쪽 전체)과 나란히 놓아, 텍스트 쪽 경로를 "직접 읽기"와 "간접 반응(다음 블록부터 바뀐 이미지 토큰을 읽음)"으로 나눈다.

## 1. 조작

- 지금 방식(모든 행): V′ = V + (λ−1)QQᵀ(V − b). 이미지 쿼리와 텍스트 쿼리가 모두 V′을 읽는다.
- 변형(이미지 행):
  - 이미지 쿼리 출력 = attention(q_img, K, [V′_img ; V_txt])
  - 텍스트 쿼리 출력 = attention(q_txt, K, [V_img ; V_txt]) (편집 전 이미지 V)
  - K, 기저 Q, 블록, step, λ의 뜻은 같다. pad 축소와 같은 방식(이미지 행만)이다.
- 두 모델에 같은 변형을 쓴다(같은 방법 원칙). 블록과 step은 지금 설정 그대로다(SD3.5 전 블록 step 0–11, FLUX 블록 19–37 step 0–5).
- 변형도 텍스트 쪽을 완전히 두지는 않는다. 다음 블록부터 텍스트 토큰은 이미 바뀐 이미지 토큰을 읽는다. 변형이 끄는 것은 같은 블록 안의 직접 읽기뿐이다.

## 2. 조건 (e06 50 prompt × seed 71000–71007, 512 px)

지금 방식 조건과 원본은 E06에서 그대로 재사용한다.

| | SD3.5 | FLUX |
|---|---|---|
| 변형, V만 (E1 축) | λ1.14, 1.2, 1.3 | λ1.72, 2.01, 2.58 |
| 변형, 조합 (pad ¼ 고정) | λ1.14, 1.2 | λ1.72, 2.01 |
| 지금 방식, 새로 만드는 비교점 | λ1.2 + pad ¼ (곡선을 늘리려고) | 없음 (λ1.43·1.72·2.01 + pad ¼가 E06·E4에 있음) |
| 재사용 | 원본, E1 7점, pad ¼, λ1.07·1.14 + pad ¼ | 원본, E1 7점, pad ¼, λ1.43·1.72·2.01 + pad ¼ |

- 새 조건은 SD3.5 6개, FLUX 5개다.
- 위쪽 λ(1.3, 2.58)는 변형이 같은 λ에서 다양성을 덜 낼 것에 대비해 넣었다. 10-31 예전 후보의 같은 조작(txt_none)에서 DINO가 19% 줄었다.
- 보충 규칙: 변형 조합의 가장 큰 평균 ΔVendi가 지금 최종점(SD3.5 +0.55, FLUX +0.77)보다 작으면, 변형 조합에 λ 한 점을 더한다(SD3.5 1.3, FLUX 2.58).

## 3. 지표

- **다양성:** Vendi(DINO)가 주 지표다. 구도·색 다양성은 보조다.
- **실제 실패:** §21.2 기준(주 대상을 알아볼 수 없음, 깨짐, 붕괴; 화풍은 판정에 쓰지 않음). 가린 시트 라벨, 25 prompt × 8 seed다.
  - 변형 조건과 비교할 지금 방식 조건(원본, 같은 λ의 V만·조합 점)을 한 묶음에 섞어 함께 라벨한다. SD3.5는 이미 2차 라벨이 있어도 다시 라벨한다. 다른 묶음의 라벨을 섞으면 라벨러 차이가 비교에 들어간다.
  - FLUX는 아직 라벨하지 않은 E06 18조건과 같은 묶음에 넣는다.
- **불일치:** 판정 모델 match < .5, 50 prompt × 8 seed.
- **MUSIQ:** 원본 대비 < −1이면 플래그다. 시트 규칙으로 판정한다.
- **보조:** VQA(구성·희귀 prompt), 판정 모델의 결함 또는 화풍(기술용).
- **직접 읽기 몫(Q2):** 같은 λ에서 ΔVendi(변형) / ΔVendi(지금). SD3.5는 λ1.14·1.2, FLUX는 λ1.72·2.01이다. E3 텍스트 스트림 고정 비율(SD3.5 0.34·0.37, FLUX 0.94·0.88)과 나란히 적는다.

## 4. 판정 (결과 보기 전에 고정)

- **주 지표:** 같은 평균 ΔVendi에서의 비용 차이다. 값 = 변형 조건의 비용 − 지금 방식 곡선의 비용이다. 곡선은 원본(0)과 조건 평균점을 잇는 꺾은선이고, 변형 조건의 평균 ΔVendi에서 선형 보간한다. prompt 짝 bootstrap 95%로 구하고, 곡선도 재표집마다 다시 그린다(E4 §20과 같은 방법). 실제 실패와 불일치를 따로 본다.
- **채택 판단은 조합으로 한다.** 실제 방법이 조합이기 때문이다. 비교점은 변형 조합 중 평균 ΔVendi가 지금 최종점(SD3.5 +0.55, FLUX +0.77)에 가장 가까운 점이다.
- **V만 비교는 서술용이다.** 비교점은 변형 V만 점 중 지금 방식 λ1.2(SD3.5)·2.01(FLUX)의 ΔVendi에 가장 가까운 점이다.
- **판정:**
  - "이미지 행 V 편집으로 바꾼다": 두 모델 모두 조합 비교점에서 다음을 모두 만족한다.
    - 실제 실패 또는 불일치 차이의 구간 상한 < 0
    - 다른 하나의 구간 하한 ≤ 0
    - MUSIQ가 지금 방식 곡선보다 1 넘게 낮지 않음
    - 변형 조합이 지금 최종점의 다양성에 닿음
  - "변형이 비용을 늘린다": 어느 모델에서든 어느 비용의 구간 하한 > 0이다.
  - 그 밖에는 "지금 방식 유지"다. 변형은 절제 결과(직접 읽기 몫, 같은 다양성에서의 비용 차이)로 보고한다.
- **검정력:** SD3.5 지금 최종점의 실제 실패는 200장 중 5장이다. 실제 실패 차이는 구간이 넓을 가능성이 크다. "차이 없음"이 나오면 구간 폭을 같이 적고, "같다"가 아니라 "차이를 보이지 못했다"로 쓴다.

## 5. 구현과 null 검사

- **코드(안):** 설정에 `v_edit.rows = all | image`를 더한다. 기본값은 all이고, 지금 동작과 같다.
  - image일 때 `image_value`가 블록마다 편집 전 이미지 V를 보관한다. `attend`는 텍스트 쿼리 출력만 편집 전 V로 계산한다.
  - FLUX는 rows=image일 때 `attend` 경로로 보낸다(`wants_attend`). pad 축소가 이미 쓰는 경로다.
- **null 검사:**
  1. rows=all은 코드 수정 전과 픽셀이 같아야 한다(두 모델, 기존 parity 시험).
  2. rows=image, λ1은 원본과 같아야 한다. rows=image, λ1 + pad ¼는 지금 pad ¼만 쓴 결과와 같아야 한다(픽셀 같음).
  3. attention 한 번 단위 시험: 변형의 이미지 행 출력은 지금 방식의 이미지 행 출력과 같고, 텍스트 행 출력은 편집 없는 출력과 같아야 한다.
  4. rows=image, λ > 1은 rows=all과 달라야 한다(두 모델).
- **FLUX 위험:** `attend` 경로는 FLUX 기본 dispatch와 수치가 다를 수 있다. 2번이 픽셀 같음으로 통과하지 않으면 허용 오차를 먼저 정하고 다시 묻는다.

## 6. 사전 예측

- **R1:** 같은 λ에서 변형의 ΔVendi는 지금 방식보다 작다. SD3.5 비율은 0.6–0.9이고, E3 텍스트 스트림 고정(0.34·0.37)보다 크다. FLUX 비율은 0.9 이상이다.
- **R2:** 같은 다양성에서 비용 차이는 두 모델 모두 구간이 0을 포함한다. 근거: E3에서 텍스트 쪽 경로는 다양성과 실제 실패를 같은 비율로 날랐다(§21.3). 그래서 "지금 방식 유지"가 가장 그럴듯한 결과다.
- **R3:** SD3.5에서 변형의 구도 다양성 비율은 0.9 이상이다. 근거: 10-31 txt_none에서 구도가 100% 남았다.

## 7. 규모와 순서

- **생성:** 11조건 × 400장이다. E06 실측(평가 포함 SD3.5 약 1.1, FLUX 약 1.6 GPU시간/조건)으로 약 15 GPU시간이다.
- **라벨:**
  - SD3.5: 변형 5조건 + 비교용 지금 방식 약 6조건 + 원본, 약 2,400장
  - FLUX: E06 18조건 + 변형 5조건, 약 4,600장
  - 하위 에이전트로 가려서 라벨한다.
- **순서:** 코드와 null → 생성 → 평가 → 라벨 → 분석.
  - FLUX E4 큐가 끝난 뒤에 넣는다.
  - FLUX 라벨은 E06 18조건 라벨을 이 생성이 끝날 때까지 미뤄 한 묶음으로 한다. 이렇게 하면 E06 FLUX 실제 실패 결과가 늦어진다.
- **held-out:** 채택이 나오면 ho4에서 확인한다. 이건 따로 정한다.

## 8. 사용자가 정할 것

1. 채택 판단을 조합으로 할지. 권고는 조합이다.
2. SD3.5 비교 조건을 같은 묶음에서 다시 라벨할지. 권고는 다시 라벨이다.
3. FLUX E06 라벨을 이 실험과 한 묶음으로 미룰지, 먼저 할지. 미루면 E06 FLUX 결과가 약 하루 늦어진다.
