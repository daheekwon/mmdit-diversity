# E3 추가 차단 설계안 (초안, 2026-11-06, 실행 전)

SD3.5 E3 결과(PROTOCOL §15)를 본 뒤에 쓴 설계안이다. 사전 등록에는 없었다. 아직 코드도 큐도 없다. 사용자가 고르면 PROTOCOL에 절로 옮기고, 판정 규칙은 결과를 보기 전에 고정한다.

## 0. 이 설계가 답하려는 두 질문

1. **기준을 원본 생성으로 해야 하나?** 지금 E3의 기준은 "같은 x_t에서 이번 step만 편집하지 않은 짝 계산"이다. 이 기준은 매 step의 텍스트 경로 몫을 막는다. 그 몫은 x_{t+1}에 들어가지 않는다. 열려 있는 것은 하나다. 이미지→이미지 길로 바뀐 이미지를 다음 step에서 텍스트 토큰이 읽고 **반응하는 것**이다. 원본 대비 변화는 대부분 step을 거치며 쌓인다(λ1.2 이미지→단어 attention JS: step 0 0.005, step 11 0.094, 편집 없는 step 12 0.088). 그래서 이 반응이 얼마나 크고, 무엇을 나르는지가 질문이다.
2. **내용(텍스트 V)은 따로 봤나?** 보지 않았다. 지금의 두 차단은 내용과 비중만 다른 게 아니다.

| | 텍스트 스트림 고정 | 단어 열 확률 고정 |
|---|---|---|
| 텍스트 토큰 내용(V) | 고정 | 열림 |
| 텍스트 쪽 key(K) | 고정 | 열림(확률만 고정) |
| 이미지 Q 쪽 비중 변화 | 열림 | 단어 열에서 고정 |
| pad·특수 토큰 | 고정 | 열림(행 합 비례 조정만) |
| SD3.5 무조건부 행 | 고정 | 열림 |

그래서 텍스트 스트림 고정이 망가짐 기울기를 더 줄인 이유(−19.6 vs −8.5 pp/Vendi)를 가를 수 없다. 내용 기록도 없다. 내부 신호는 단어 토큰의 K만 기록했다.

## 1. 바탕: 텍스트 스트림 고정을 "이미지 쿼리가 읽는 값"으로 다시 쓰기

joint attention에서 텍스트가 이미지 토큰에 닿는 길은 하나다. 이미지 쿼리가 텍스트 열의 K와 V를 읽는 것이다. adaLN은 시간·pooled 임베딩에서 오고, MLP는 토큰별이다. SD3.5의 두 번째 attention은 이미지 토큰만 쓴다.

텍스트 스트림 고정에서 본 계산의 텍스트 출력은 다음 블록 입력에서 버려진다. 그래서 텍스트 스트림 고정은 아래와 같다.

> 모든 블록에서 이미지 쿼리가 **텍스트 열 전부의 K와 V를 짝 계산의 값으로** 읽는다(두 CFG 행).

이 형태로 쓰면 K와 V, 단어 토큰과 pad·특수 토큰을 따로 막을 수 있다. 아래 A는 모두 이 형태이고 기준은 E3와 같은 짝 계산이다. 그래서 E3 텍스트 스트림 고정을 그대로 쪼갠다.

## 2. A: 텍스트 경로 쪼개기 (질문 2)

**조건.** SD3.5 이미지 V λ1.2(pad 끔), 편집 step 0–11, e06 50 prompt × 8 seed.

| 이름(코드) | 이미지 쿼리가 짝 값으로 읽는 것 | 남는 것 |
|---|---|---|
| `v_l1.2+readkv` | 텍스트 열 전부의 K와 V | 이미지 Q 쪽 비중 변화. 텍스트 스트림 고정과 같은 조작이고, 같은 구현 안의 기준이다 |
| `v_l1.2+readv` | 텍스트 열 전부의 V만 | 텍스트 K 변화(비중), 이미지 Q 쪽 비중 변화 |
| `v_l1.2+readk` | 텍스트 열 전부의 K만 | 텍스트 내용 변화, 이미지 Q 쪽 비중 변화 |
| `v_l1.2+readwkv` | 단어 토큰 열의 K와 V만 | pad·특수 토큰의 K·V 변화, 이미지 Q 쪽 비중 변화 |

- λ는 1.2 한 점이다. E3에서 차이가 가장 컸던 점이다(판독 망가짐 64장 → 11장). λ1.14는 A에서 쓸 만한 차단이 나올 때만 더한다.
- 빠진 것과 이유:
  - SD3.5 무조건부 행만 따로 막는 조건. 단어 열 확률 고정과 텍스트 스트림 고정의 행 차이는 이 설계로도 설명되지 않는다.
  - pad 조건. SD3.5 pad 0에는 원래 비용이 없었다(§15).

**판정 (결과를 보기 전에 고정).**
- 차단마다 편집만(v_l1.2)과 §5 규칙 그대로 비교한다.
  - 망가짐 기울기 차이(원점 직선, prompt bootstrap 2000)의 구간 < 0 → "깨짐 줄어듦".
  - ΔVendi 비(차단/편집만) < 0.5 → "다양성도 줄어듦".
  - 둘을 합쳐 §5의 네 분기로 적는다.
- **"깨짐만 줄어듦"이 나와도 바로 가드로 쓰지 않는다.** 결과를 본 뒤 더한 조건이고, 차단이 여럿이라 우연히 하나가 통과할 수 있다. ho4(held-out 24 prompt × 16 seed)에서 같은 규칙으로 다시 통과해야 E4 후보가 된다.
- 쪼개기(기술 통계, 판정 아님):
  - 몫 = (편집만 − 차단) / (편집만 − `readkv`). 망가짐 비율과 ΔVendi에 대해 각각 구한다.
  - `readk` 몫 + `readv` 몫이 1에서 벗어나는 정도를 K와 V의 상호작용으로 적는다.
  - `readwkv` 몫이 1에 가까우면 단어 토큰이, 0에 가까우면 pad·특수 토큰이 나른다.
- 시트: §15와 같은 prompt 6개 + 망가짐 이미지 시트. 만화·일러스트 전환이 어느 차단에서 사라지는지 본다.
- 방향 예측은 적지 않는다. 내용과 key 중 어느 쪽인지 정할 근거가 지금 없다.

**구현.**
- 짝 계산에서 블록마다 텍스트 열의 K(정규화 뒤, attention이 받는 값)와 V를 저장한다. 두 행 모두다. SD3.5는 약 0.8 GB다.
- 본 계산의 이미지 쿼리 출력에 보정항을 더한다: SDPA(q_img, K′, V′) − SDPA(q_img, K, V). 두 항은 fp32, 같은 연산 순서로 계산한다. K′, V′는 정해진 열만 짝 값으로 바꾼 것이다.
- 단어 열 확률 고정과 같은 방식이다. 짝 = 본 계산이면 보정이 정확히 0이다.

**null 검사.**
1. λ1 + 네 차단 = 원본(픽셀 같음).
2. 차단 플래그 없는 새 코드 = 편집만(픽셀 같음).
3. 참고만: `readkv` 대 기존 텍스트 스트림 고정 이미지의 픽셀 차이를 적는다. 보정항(fp32)과 실제 재계산(bf16)이 달라서 0은 아닐 것이다. 판정에는 `readkv`를 기준으로 쓴다.

## 3. B: 바뀐 이미지에 대한 텍스트 반응 (질문 1)

### B0. 반응 크기 재기 (먼저, 싸다)

새 생성 판정 없이, 내부 신호만 잰다.

- 조건: 원본, v_l1.2, v_l1.2+텍스트 스트림 고정, v_l1.2+단어 열 확률 고정. 50 prompt × seed 71000·71001. step 0·1·11·12.
- 지표(원본 대비, 같은 seed, 블록 평균):
  - 단어 토큰 K 1 − 코사인(기존 신호).
  - 텍스트 V 1 − 코사인. **새로 기록**하고, 단어 토큰과 pad·특수 토큰을 따로 낸다. K처럼 고정 무작위 128차원 사영으로 저장한다.
- 텍스트 스트림 고정 run에서 본 계산의 텍스트 K·V는 짝 계산의 값이다. 짝 계산은 그 step의 x_t에서 돈다. 그래서 이 run의 원본 대비 변화가 곧 **반응의 크기**다.
- 판정: 남은 비율 = 텍스트 스트림 고정 run의 변화 / 편집만 run의 변화(step 11, 단어 토큰 K 기준. V는 같이 적는다).
  - ≥ 0.5: 반응이 크다. B1을 제안한다.
  - < 0.5: 짝 기준 차단이 텍스트 변화의 대부분을 이미 없앴다. 원본 기준은 더할 것이 적다. B1은 하지 않는다.
- 이 측정은 A의 "내용 기록 없음"도 같이 메운다.

### B1. 원본 기준 텍스트 고정 (B0가 ≥ 0.5일 때만)

- 조건: `v_l1.2+origtxt`. 이미지 쿼리가 텍스트 열 전부의 K와 V를 **원본 생성의 같은 step·블록 값으로** 읽는다(두 행). step 0–11이다. 그 밖은 E3와 같다.
- 구현:
  - 배치마다 먼저 원본(편집 없음)을 돌리며 step 0–11의 latent를 저장한다.
  - 편집 run의 짝 계산 입력을 그 latent로 바꾼다(SD3.5는 CFG 두 행으로 복제).
  - 나머지는 A의 `readkv`와 같다.
- null 검사:
  1. λ1 → 원본(픽셀 같음).
  2. 저장한 원본 run의 이미지 = 기존 원본 이미지(픽셀 같음).
  3. step 0의 짝 입력 = 본 계산 입력(같은 noise).
- **해석의 한계(먼저 밝힘).** 원본 기준에서는 편집된 이미지 토큰이 다른 이미지(원본)를 요약한 텍스트를 읽는다. 그래서 "이 길을 막음"과 "원본 쪽으로 끌어당김"을 조작으로 가를 수 없다. 그래서 판정을 비대칭으로 정한다. 비교 대상은 같은 λ의 `readkv`(짝 기준)다.
  - ΔVendi 비(`origtxt`/`readkv`)의 구간이 1을 포함하거나 1보다 크고, 망가짐 기울기 차이의 구간이 0을 포함하면: "바뀐 이미지에 대한 텍스트 반응은 다양성도 깨짐도 더 나르지 않는다". 이 결과만 그대로 해석한다.
  - ΔVendi나 망가짐이 더 줄면: 반응 경로 몫의 **상한**으로만 적는다. 원본 쪽 끌림과 가를 수 없다.
  - 망가짐(특히 defect)이 `readkv`보다 늘면: 어긋난 상태 자체의 해로 적는다.
- step 12–27까지 원본 기준으로 고정하는 변형은 넣지 않는다. 어긋남이 더 커져 해석이 더 어렵다.

## 4. 범위, 순서, 비용

- SD3.5 먼저. 논문 주장에 쓰려면 FLUX에서 같은 조건(같은 모듈, 같은 조작)을 돈다. FLUX 점은 FLUX E3 결과를 본 뒤 E3 위쪽 점(λ2.01)을 기본으로 정한다.
- 순서: A와 B0는 서로 독립이라 같이 돌 수 있다. B1은 B0 판정 뒤다.
- 비용(SD3.5, E3 로그 기준: 짝 + 고정 조건 1개 = prompt당 8장에 33–45초, GPU당 2작업):

| 묶음 | 내용 | 생성 | 평가 |
|---|---|---|---|
| A | 4조건 × 400장 | 약 2.5 GPU시간 | 약 1 GPU시간 |
| B0 | 4조건 × 100장, 신호만 | 약 0.5 GPU시간 | 없음 |
| B1 | 1조건 × 400장 + 원본 재생성 | 약 1 GPU시간 | 약 0.3 GPU시간 |

- 코드 변경: `probe.py`(짝 계산의 텍스트 K·V 저장, 보정항, 텍스트 V 신호, 원본 latent 입력), `common.py`(조건 이름), `run_probe.py`(null 검사), `analyze_e3.py`(새 절).
- `probe.py`는 다른 세션의 DAVE·FLUX 작업도 쓴다. 고치기 전에 그 작업이 끝났는지 확인한다.
